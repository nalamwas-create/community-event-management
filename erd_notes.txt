COMMUNITY EVENT MANAGEMENT SYSTEM
DATABASE DESIGN

1. MEMBERS
- member_id INT PRIMARY KEY
- name VARCHAR(100)
- email VARCHAR(100)
- phone VARCHAR(20)

2. STAFF
- staff_id INT PRIMARY KEY
- name VARCHAR(100)
- email VARCHAR(100)
- phone VARCHAR(20)

3. VENUES
- venue_id INT PRIMARY KEY
- venue_name VARCHAR(100)
- floor_number INT
- seating_capacity INT

4. EVENTS
- event_id INT PRIMARY KEY
- event_name VARCHAR(150)
- event_date DATE
- venue_id INT FOREIGN KEY
- staff_id INT FOREIGN KEY

5. REGISTRATIONS
- registration_id INT PRIMARY KEY
- member_id INT FOREIGN KEY
- event_id INT FOREIGN KEY
- registration_date DATETIME


RELATIONSHIPS

STAFF 1 ---- MANY EVENTS
One staff member can organize many events.
Each event is organized by one staff member.

VENUES 1 ---- MANY EVENTS
One venue can host many events.
Each event is assigned to one venue.

MEMBERS 1 ---- MANY REGISTRATIONS
One member can have many registrations.
Each registration belongs to one member.

EVENTS 1 ---- MANY REGISTRATIONS
One event can have many registrations.
Each registration belongs to one event.

MEMBERS MANY ---- MANY EVENTS
A member can register for many events.
An event can have many members.
This many-to-many relationship is resolved through REGISTRATIONS.
